# Interview Guide

Use this reference to obtain the smallest amount of information that materially improves the panel.

## Evidence-first question policy

1. Extract what the user already supplied.
2. Map evidence to domains and mark gaps.
3. Rank gaps by effect on the user's purpose.
4. Ask one concrete question.
5. Update the panel or ledger before asking another.

Prefer examples over identity labels:

- Better: “讲一个最近让你很有成就感的具体结果。”
- Weaker: “你觉得自己执行力几分？”

## Mode guides

### Quick scan

Ask no questions when the existing material supports a useful first panel. If one is necessary, choose the highest-yield question:

1. What is this panel for: self-understanding, public introduction, career planning, collaboration, or fun?
2. What current outcome matters most?
3. What recent evidence best shows a signature strength?
4. What repeatedly blocks progress?
5. What must stay private or off-panel?

Return the panel after no more than five answers.

### Deep build

Move in passes:

1. **Now:** roles, current chapter, goals, constraints.
2. **Evidence:** achievements, artifacts, repeated behaviors, feedback.
3. **Inner rules:** values, motives, boundaries, trade-offs.
4. **World:** relationships, environment, resources, public image.
5. **Growth:** risks, recovery, quests, success signals.

Ask one question per turn. Summarize what changed after each pass.

### Source conversion

Extract first. Ask only for:

- ambiguous identity;
- conflicting dates or claims;
- display permission;
- a missing purpose that changes output shape.

Do not ask the user to restate facts present in a resume, biography, notes, or chat.

### Update

For each changed claim, capture:

```text
old value | old source/date | new value | new source/date | relation
```

The relation is `supports`, `narrows`, `supersedes`, or `conflicts`. A newer claim does not automatically erase an older observation; context may differ.

## No-question fallback

Activate when the user says not to ask, asks for an immediate result, is unavailable, or supplied a batch request.

Deliver:

1. a useful supported panel;
2. visible unknowns instead of invented detail;
3. up to five `next unlocks`, phrased as optional information that would most improve the next version;
4. no blocking question.

Example:

```markdown
## Next unlocks

- One finished project with an outcome would unlock a craft score.
- A recent setback-and-recovery example would unlock resilience.
- Your preferred public/private boundary would finalize display settings.
```

## Question quality check

A good question:

- changes a decision or visible field;
- asks for one thing;
- is answerable from memory;
- does not demand sensitive disclosure;
- invites “skip” or “keep private” when appropriate.

Avoid personality quizzes, exhaustive forms, repeated self-ratings, and questions that exist only to fill the template.
