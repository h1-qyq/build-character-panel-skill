# Attribute System

Use this reference for full panels, domain gap checks, and consistent field meanings. Domains organize evidence; they are not a requirement to display private information.

## The 18 domains

| ID | Covers | Useful panel elements |
|---|---|---|
| `identity` | Chosen name, pronouns when supplied, self-description, languages, presentation | Character name, title, archetype |
| `roles-context` | Current roles, responsibilities, stage, operating environment | Class, current chapter |
| `origin-story` | Formative events and transitions explicitly shared | Origin, turning points |
| `values-boundaries` | Principles, non-negotiables, preferences, privacy | Values, code, boundaries |
| `motives-needs` | Stated goals, needs, fears, anti-goals | Drivers, win/loss conditions |
| `personality-behavior` | Repeated context-linked behavior | Traits with evidence |
| `cognition-learning` | Learning, reasoning, creativity, decision patterns | Learning style, strategy |
| `communication-social` | Expression, listening, collaboration, conflict | Social and communication skills |
| `relationships-environments` | Teams, communities, allies, compatible settings | Party, guild, habitat |
| `capabilities-craft` | Demonstrated skills, knowledge, tools, quality | Skill tree, mastery |
| `habits-energy` | Routines, workload, recovery, energy only when supplied | Buff/debuff cycles |
| `resources-constraints` | Time, money ranges, credentials, networks, tools, limits | Inventory, equipment, leverage |
| `aesthetic-public-image` | Style, taste, signals, desired impression | Skin, visual language, aura |
| `digital-presence` | Public platforms, portfolio, reputation, discoverability | Public profile, channels |
| `achievements-arcs` | Outcomes, milestones, proof, unfinished work | Achievements, open arcs |
| `quests-missions` | Goals, projects, next actions, success signals | Main and side quests |
| `risks-recovery` | Blockers, failure patterns, mitigations, recovery | Risks, debuffs, counters |
| `growth-history` | Versions, changes, experiments, lessons | XP log, patch notes |

For a full profile, assign each domain one coverage state:

- `known`: enough supported detail to summarize;
- `partial`: some useful evidence, material gaps remain;
- `unknown`: no support;
- `conflicted`: material evidence disagrees.

## Neutral core attributes

These seven attributes avoid moral ranking. Rename labels to fit the user's world, but keep meanings stable.

| ID | Meaning | Evidence examples |
|---|---|---|
| `vitality` | Sustainable usable energy in the stated context | Repeated schedule, recovery pattern, activity record |
| `focus` | Ability to protect attention and finish bounded work | Delivery history, deep-work examples, interruption pattern |
| `learning` | Speed and reliability of acquiring and applying knowledge | New-tool adoption, feedback integration, transfer |
| `craft` | Demonstrated quality and depth in a specific practice | Artifacts, outcomes, peer/client evidence |
| `agency` | Turning intentions into self-directed action under constraints | Initiated projects, decisions, follow-through |
| `social` | Contextual communication and collaboration effectiveness | Team outcomes, negotiation, listening, facilitation |
| `resilience` | Recovery and adaptation after setbacks | Documented response, revised strategy, sustained return |

Do not show a score for an attribute merely because it is in the default set.

## Character elements

### Archetype

Write a memorable two-to-six-word synthesis supported by at least two domains. Mark it `inferred` unless the person chose it.

### Level

Level is optional. Use one of these explicit systems:

- milestone level: number of defined milestones reached;
- chapter level: named stage with no number;
- skill-specific level: 1–5 anchor for a demonstrated skill.

Never equate age, salary, followers, or social status with character level.

### Traits

A trait describes a repeated pattern across contexts. A single incident is an event; a current condition is a status effect. Phrase inferred traits conditionally:

```text
When deadlines are externally fixed, delivery appears more consistent.
```

### Values and boundaries

Keep `value`, `preference`, and `boundary` distinct:

- value: principle guiding trade-offs;
- preference: favored option that may change;
- boundary: limit the person does not consent to cross.

### Skills

Use five portable levels:

1. `novice`: can perform a bounded task with guidance;
2. `practitioner`: completes standard work independently;
3. `proficient`: handles variation reliably and explains choices;
4. `advanced`: solves ambiguous cases and raises others' quality;
5. `mastery-evidenced`: produces sustained exceptional outcomes and evolves the practice.

Unknown is not level 0.

### Resources and equipment

Use categories `tool`, `credential`, `network`, `time`, `capital`, `asset`, and `environment`. Financial or contact detail should be ranged, summarized, or omitted unless exact display is explicitly requested.

### Quests

- `active`: currently pursued and has a next action;
- `planned`: intentionally queued;
- `blocked`: desired but waiting on a named condition;
- `complete`: success signal achieved.

### Status effects

Use `buff`, `debuff`, or `mixed`. Include scope and recovery/countermeasure when known. Never infer a medical explanation.
